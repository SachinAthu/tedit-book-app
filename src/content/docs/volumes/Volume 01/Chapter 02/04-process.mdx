So far in this chapter, we have learned about two fundamental components of a computer system.

The **CPU** executes instructions, while **RAM** stores the instructions and data that those instructions operate on.

However, these two components alone are not enough to run software. A computer often runs many programs simultaneously. At this very moment, your system might be running a web browser, a music player, a terminal emulator, a file manager, a text editor, and dozens of background services.

How does the operating system keep all of these programs organized?

The answer lies in the concept of a **process**.

Understanding processes is essential because our text editor will run as a process managed by the operating system. Everything our editor does—reading keyboard input, displaying text, opening files, and responding to user commands—will happen within the context of this process.

## What Is a Process?

A **process** is a **running instance of a program**.

This distinction is extremely important.

A **program** is simply a collection of instructions stored on permanent storage, such as an SSD or hard drive. It does nothing by itself.

A **process** is what the operating system creates when it loads a program into memory and begins executing it.

You can think of it this way:

```text
Program (Stored on Disk)

editor

        │ Launch
        ▼

Running Process

CPU executing instructions
Memory allocated
Resources assigned
```

A useful analogy is a recipe and a chef.

A recipe written in a cookbook is like a program. It contains instructions but cannot prepare a meal on its own.

A chef following that recipe is like a process. The instructions are now being executed.

The recipe remains unchanged, but the chef is actively performing the work.

Similarly, a program is passive, while a process is active.

## A Program Can Have Multiple Processes

One program is not limited to a single process.

Imagine opening two separate terminal windows and running the same program in both.

```bash
./editor notes.txt
```

in one terminal, and

```bash
./editor report.txt
```

in another.

Although both processes execute the same program, they are completely independent.

```text
          editor
     (Executable File)
             │
      ┌──────┴──────┐
      ▼             ▼
+------------+ +------------+
| Process A  | | Process B  |
| notes.txt  | | report.txt |
+------------+ +------------+
```

Each process has its own memory, its own variables, its own open files, and its own execution state.

Closing one process does not affect the other.

This ability to create multiple independent instances of the same program is fundamental to modern operating systems.

## What Does a Process Contain?

A process is much more than executable code.

The operating system provides every process with the resources it needs to run.

Conceptually, a process contains:

```text
+--------------------------------+
| Program Instructions           |
+--------------------------------+
| Variables and Data             |
+--------------------------------+
| Stack                          |
+--------------------------------+
| Heap                           |
+--------------------------------+
| CPU Registers                  |
+--------------------------------+
| Open Files                     |
+--------------------------------+
| Process Information            |
+--------------------------------+
```

Let's briefly examine these components.

### Program Instructions

These are the machine instructions generated by the compiler.

The CPU executes these instructions one by one.

### Variables and Data

Every variable created by your program occupies memory.

For example,

```c
int counter = 0;
char filename[256];
```

Both `counter` and `filename` exist inside the process's memory.

### Stack

The stack stores information related to function calls.

Whenever a function is called, the operating system allocates space on the stack for local variables, function parameters, and the return address.

For now, it is enough to remember that the stack automatically grows and shrinks as functions are called and return.

### Heap

The heap is used for memory allocated during program execution.

Functions such as `malloc()` obtain memory from the heap.

Our text editor will later use dynamically allocated memory to store documents whose sizes are not known in advance.

### CPU Registers

Although registers physically reside inside the CPU, their values are considered part of the process's execution state.

When the operating system switches from one process to another, it saves the current register values so that execution can resume later exactly where it stopped.

### Open Files

A process may have several files open simultaneously.

For example, our editor might have:

- the document being edited,
- a configuration file,
- a log file.

The operating system keeps track of all these open resources.

## Every Process Has an Identity

To manage many running programs, the operating system assigns each process a unique identifier called the **Process ID**, or **PID**.

For example,

```text
PID 1024  Terminal

PID 1847  Text Editor

PID 2156  Web Browser
```

No two running processes have the same PID at the same time.

The operating system uses this identifier whenever it needs to communicate with or manage a particular process.

Later in the book, we'll see that many system calls require a PID to identify the target process.

## The Operating System Manages Processes

Processes do not run independently.

The operating system acts as their manager.

Its responsibilities include:

- creating new processes,
- terminating finished processes,
- allocating memory,
- providing access to files,
- scheduling CPU time,
- protecting one process from another.

Conceptually, the relationship looks like this:

```text
               Operating System
                     │
      ┌──────────────┼──────────────┐
      ▼              ▼              ▼
+------------+ +------------+ +------------+
| Process A  | | Process B  | | Process C  |
+------------+ +------------+ +------------+
```

Rather than allowing processes to control hardware directly, the operating system coordinates access to shared resources.

This makes modern multitasking possible.

## Processes and Our Text Editor

When we launch our editor, the operating system creates a new process.

Initially, the process contains the program's instructions but no document.

After the user opens a file, the document is loaded into the process's memory.

```text
Storage Device

notes.txt
      │
      ▼

+-----------------------------+
| Editor Process              |
|                             |
| Program Instructions        |
| Text Buffer                 |
| Cursor Position             |
| Screen Information          |
| Current Filename            |
+-----------------------------+
```

As the user types, the process updates its internal state.

Notice that these changes affect only this particular process.

If another instance of the editor is running, it maintains its own completely separate state.

This isolation is one of the reasons why applications can run independently without interfering with one another.

## Process Lifetime

Every process follows a simple life cycle.

```text
        Program on Disk
               │
          User Launches
               │
               ▼
      Process Created
               │
               ▼
      Process Running
               │
               ▼
      Process Terminates
               │
               ▼
      Resources Released
```

When the process terminates, the operating system releases its memory, closes its open files, and reclaims the resources it was using.

If the program is launched again later, an entirely new process is created.

<Aside type="tip" title="Engineering Insights" icon="rocket">

A common beginner misconception is to think of an application and a process as the same thing.

They are closely related but fundamentally different.

The executable file stored on disk is passive. It contains instructions but performs no work.

The process is the active execution of those instructions. It owns memory, open files, CPU state, and every other resource required while the program is running.

This distinction explains why you can launch multiple independent copies of the same application without them interfering with each other.

</Aside>

## Common Mistakes

### Mistake 1 — Confusing a program with a process

A program is a file stored on disk. A process is a running instance of that program.

### Mistake 2 — Thinking every program has only one process

The same program can have many processes running simultaneously, each with its own independent state.

### Mistake 3 — Assuming processes share all their memory

By default, each process has its own separate address space. One process cannot directly access another process's memory. This isolation improves both stability and security.

## Summary

A process is a running instance of a program created and managed by the operating system. It includes not only the program's instructions but also its memory, CPU state, open files, and other resources required during execution.

Every time our text editor is launched, the operating system creates a new process. This process maintains its own document, cursor position, editor state, and other data independently of any other running applications.

In the next section, we'll examine one of the most important communication mechanisms provided by Unix-like operating systems: **standard input (`stdin`) and standard output (`stdout`)**. These streams allow programs to receive input and produce output without needing to know where that input comes from or where the output will ultimately be displayed.
