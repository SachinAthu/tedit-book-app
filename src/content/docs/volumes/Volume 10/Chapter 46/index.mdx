## Introduction

Chapter 45 ended with a working runtime: the terminal entered raw mode, an event loop received input, and shutdown restored the terminal. But that program still had nothing to edit. Chapter 46 turns the runtime into an editor by building the first editable screen.

> **How do the document, cursor, editor state, screen buffer, and renderer come together to produce an interactive editing experience without breaking the architecture?**

The chapter proceeds in small, verifiable steps. It implements an in-memory Document, a logical Cursor, a central Editor State, and a contiguous Screen Buffer, then adds a Renderer that reads editor state without modifying it. Once these components can build a frame, they are integrated into the application lifecycle, and the event loop begins accepting printable ASCII characters, inserting them at the cursor, and redrawing after each input. The chapter ends by verifying the build, exercising the runtime manually in a terminal, and checking the architectural boundaries. File loading, deletion, line splitting, and UTF-8 remain deliberately out of scope; the goal is the first working editable screen, not the finished editor.
