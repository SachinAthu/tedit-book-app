## Viewport implementation

The Viewport stores two offsets, consistent with ADR-019:

```c
typedef struct
{
    size_t viewport_row;
    size_t viewport_column;
} Viewport;
```

- `viewport_row` identifies the first visible logical document row.
- `viewport_column` identifies the first visible display column.

The Viewport does not copy or modify the Document.

The central function is `viewport_ensure_cursor_visible()`:

```c
bool viewport_ensure_cursor_visible(
    Viewport *viewport,
    size_t cursor_row,
    size_t cursor_visual_column,
    size_t screen_rows,
    size_t screen_columns)
{
    if (viewport == NULL ||
        screen_rows == 0 ||
        screen_columns == 0)
    {
        return false;
    }

    if (cursor_row < viewport->viewport_row)
    {
        viewport->viewport_row = cursor_row;
    }
    else if (cursor_row - viewport->viewport_row >= screen_rows)
    {
        viewport->viewport_row = cursor_row - screen_rows + 1;
    }

    if (cursor_visual_column < viewport->viewport_column)
    {
        viewport->viewport_column = cursor_visual_column;
    }
    else if (cursor_visual_column - viewport->viewport_column >= screen_columns)
    {
        viewport->viewport_column = cursor_visual_column - screen_columns + 1;
    }

    return true;
}
```

The function adjusts the offsets only when the Cursor would otherwise fall outside the visible area. It rejects invalid arguments and zero-sized screen dimensions.

## Renderer integration

The Renderer now maps screen coordinates to document coordinates:

```c
size_t document_row = state->viewport.viewport_row + screen_row;

size_t document_column = state->viewport.viewport_column + screen_column;
```

The Renderer copies only the visible portion of each logical line into the Screen Buffer. It also positions the terminal Cursor relative to the Viewport offsets.

The application calls `viewport_ensure_cursor_visible()` before rendering. This keeps the Viewport update in the application flow while the Renderer remains a read-only consumer of Editor State.

## Current implementation boundary

The current input implementation accepts printable ASCII only. Consequently, logical columns and visual columns coincide for the supported input.

Tab expansion and Unicode display-width mapping are not implemented yet. Those must be handled at the Renderer boundary before horizontal scrolling can correctly support variable-width characters.
