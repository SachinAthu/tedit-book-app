## Introduction

Chapter 50 let the editor open a file and edit it in memory, but no edit could be persisted. The Dirty Flag recorded that changes existed; nothing yet turned those changes back into bytes on disk.

> **How should the editor safely serialize a document back to UTF-8, replace a file without corrupting it, and know when saving has actually succeeded?**

This chapter adds saving to the File Manager following the project's decisions on encoding and file safety. It serializes the Document to UTF-8 with LF endings, writes to a temporary file in the destination directory, handles partial writes and errors, and atomically replaces the target with `rename()`. The Dirty Flag clears only after that replacement succeeds; failures preserve both the in-memory document and the existing file. It then connects saving to Editor State and the event loop through Ctrl-S, and reviews the failure paths, including zero-line documents and replacement errors. Durability via `fsync()`, metadata preservation, Save As, and unnamed-file saving remain out of scope.
