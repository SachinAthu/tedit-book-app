> Every programmer uses a text editor. Few programmers understand how one actually works.

We spend thousands of hours inside Nano, Vim, Emacs, and VS Code — but most of us never stop to ask what's happening underneath. How does a keypress reach your program? How is text stored in memory? Why does inserting into a huge file sometimes feel slow?

This book answers those questions by building a real terminal text editor from scratch in C. Along the way you'll pick up the systems programming, data structures, and architecture ideas that power every editor — and every interactive program.

## What you'll build

By the end, you'll have a working, Nano-like editor that can open, edit, and save files, move the cursor, scroll, and more. It's deliberately simple — but it's built from the same architectural blocks used by much larger editors.

## Where this book came from

I've always been interested in text editors. I built clones of popular web-based editors like Medium and Hashnode using third-party packages, but I never built one from the ground up. I wanted to understand how an editor really works, so I decided to build one from scratch.

This book started as a collection of ChatGPT prompts I used to learn how editors work and build a baseline Nano-like terminal text editor. That journey eventually grew into a full book, so you can follow the same path — from first principles to a working editor.

  start building sooner. A good route: Volume I for how terminals work, Volume

  actually implement — then jump into Volume X and dip back into the theory
